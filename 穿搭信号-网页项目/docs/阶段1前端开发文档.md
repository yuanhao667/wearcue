# 阶段 1 前端开发文档

## 本阶段闭环

1. 默认读取后端保存的北京设置并获取当天气温范围。
2. 按通勤、约会、出行请求正式推荐，支持“换一套”。
3. 上传 JPEG、PNG 或 WebP 图片，调用后端识别工作流。
4. 用户核对衣物、颜色、薄厚与场景后，保存为收藏或加入推荐池。
5. 在衣橱中查看推荐池和收藏，并可切换状态。
6. 设置城市、男女素材库、冷热偏移和晨间提醒。

## 页面结构

- `/`：今日天气与穿搭推荐。
- `/inspiration`：上传、识别、确认与保存。
- `/closet`：推荐池与收藏。
- `/settings`：个人偏好。

## 状态约定

所有业务页面都明确处理 `loading`、`empty`、`error`、`waiting_user` 和 `success`。错误信息优先使用后端返回的中文 `detail`，并提供就地重试。

## 验收标准

- 390、768、1280 和 1440 像素宽度下无横向溢出。
- 首页温度显示全天范围而非单点温度。
- 换一套会排除当前方案并请求后端。
- 上传结果必须由用户确认后才进入衣橱。
- 页面不依赖本地模拟业务数据或 localStorage 业务档案。
- 通过 lint、TypeScript、单元测试、生产构建及真实浏览器检查。
